# Step 11A — User Review (PWA Packaging)

**What Step 11 covers:** Converting the Pygbag browser game into an installable,
offline-capable Progressive Web App (PWA) by adding a web app manifest, a service
worker, app icons, and a customised Pygbag HTML template.

---

## 1. Run the dev server

```bash
cd F:/Python/Avalanche
bash run_dev.sh
```

Serves on **http://localhost:8000**. First fresh-browser load ~30 s.

## 3. Verify the manifest is served

Open DevTools → **Application** tab → **Manifest** (left sidebar).

You should see:
- **Name:** Avalanche
- **Short name:** Avalanche
- **Display:** standalone
- **Orientation:** landscape
- **Theme color:** #000000
- **Background color:** #000000
- **Icons:** at least two entries (192×192 and 512×512)

If the manifest section is missing or shows errors, the service worker will also
fail to install. Fix before proceeding.

---

## 4. Verify the service worker registers

Still in **Application** → **Service Workers** (left sidebar):

- **Status:** should show `activated and is running` (or `waiting to activate` on
  the very first load — refresh once).
- **Scope:** `http://localhost:8000/`
- No error messages.

Check the **Console** tab — you should see:
```
[SW] registered, scope: http://localhost:8000/
```

---

## 5. Verify canvas auto-focus

Load the page. When the loading infobox disappears and the game title screen
appears **do not click**. Immediately press any key (SPACE, WASD, Enter).

- **Expected:** the title screen reacts — the game advances to Wave 1 banner.
- **Prior behaviour:** keypress was silently ignored until the user clicked the canvas.

If a click is still required, the `custom_postrun()` hook is not firing.

---

## 6. Verify the install prompt (Chrome only)

1. Open `http://localhost:8000` in Chrome.
2. Look for the **install icon** (monitor with a ↓ arrow) in the address bar, **or**
   open the Chrome menu (⋮) and look for **"Install Avalanche…"** or
   **"Add to Home screen"**.
3. Click install. A standalone window (no browser chrome) should open with the game.
4. The window title should read **"Avalanche"**.
5. The taskbar/dock entry should show the gold cube icon.

> **Note:** The install prompt only appears when Chrome judges the PWA meets
> installability criteria. On localhost, HTTPS is not required but Chrome may
> take a few seconds to recognise the manifest and SW as valid. Hard-reload
> (`Ctrl+Shift+R`) if the prompt does not appear within ~5 s of the SW
> activating.

---

## 7. Verify offline functionality

1. After the game has loaded once (SW activated and shell cached), open
   DevTools → **Network** tab → tick **Offline**.
2. Hard-reload (`Ctrl+Shift+R`).
3. **Expected:** `index.html`, `manifest.json`, and the icons load from cache.
   The game itself may not run offline on the first visit (CDN WASM is not
   cached by the SW — by design, to avoid opaque-response quota issues), but
   the shell page loads without a network error.
4. Untick **Offline** before continuing.

---

## 8. Verify black loading background

Before the WASM runtime initialises, the page should be **solid black** — not
grey, not powder blue. Check both the `<body>` background and the area outside
the canvas.

---

## 9. Success criteria

- [ ] **Manifest visible** in DevTools → Application → Manifest with correct fields.
- [ ] **Service worker active** — shows `activated and is running` in Application → Service Workers.
- [ ] **Canvas auto-focus** — keypress immediately after load advances the game
      without a manual click.
- [ ] **Install prompt** appears in Chrome address bar or menu.
- [ ] **Install works** — standalone window opens with correct title and icon.
- [ ] **Black background** — loading screen is black, not grey or blue.
- [ ] **Shell caches offline** — page loads (possibly without game runtime) after
      toggling DevTools → Network → Offline.
- [ ] **No console errors** across the full game flow (load → play → game over →
      restart).

---

## 10. Intentionally out of scope for Step 11

- **Full offline gameplay** — The CDN Python/WASM runtime (`pythons.js` and
  accompanying WASM) is not cached by the SW to avoid opaque-response quota
  issues. Fully offline play would require either self-hosting the WASM or
  using a more complex cache strategy. Deferred.
- **Lighthouse PWA audit score** — A perfect Lighthouse score requires HTTPS
  (localhost is treated as secure but DevTools Lighthouse may flag `start_url`
  caching). Run Lighthouse against the deployed URL for a production audit.
- **Splash screen image** — The `screenshots` manifest field for an enhanced
  Chrome install dialog has not been added; it requires a captured screenshot.
- **Audio** — Still deferred throughout the project.

## 11. Expert Panel findings (Step 11A)

| Reviewer | Verdict | Finding | Resolution |
|---|---|---|---|
| Vision Lead | APPROVED | Name, description, display, orientation, icon design all faithful to retro identity. Suggested `categories` and `lang` fields. | `"lang": "en"` and `"categories": ["games"]` added to manifest. |
| Code Quality | CONCERNS → APPROVED | Three Power-of-Ten violations in `scripts/make_icons.py`: Rule 2 (`_draw_line` while-loop guard must be `assert`), Rule 5 (`_thick_edge` missing thickness precondition), Rule 9 (`Path(__file__).parent.parent` is a 3-chain). | All three fixed. |
| UX Tester | CONCERNS → APPROVED | `display: "fullscreen"` traps mobile users with no system back affordance. `"purpose": "any maskable"` combined value may break adaptive icons on Android 8+. | Changed to `display: "standalone"`. Icon purposes split into separate `"any"` and `"maskable"` entries. |
| Platform Engineer | CONCERNS → APPROVED | (1) `favicon.png` in `SHELL_URLS` but not in `static/` — SW install fails on fresh build. (2) CDN cross-origin WASM should not be cached (opaque quota risk). `'/'` + `'/index.html'` redundant. | (1) `favicon.png` removed from `SHELL_URLS`; cached lazily by `_cacheFirst`. (2) Same-origin guard added to SW fetch handler — CDN requests pass through unmodified. `'/'` removed from SHELL_URLS. |
